### LTM writes

`long-term-memory/emr-integration.md` (+~55 lines) — *Result content correctness: the vocabulary
you don't own*:
- `OUT_OF_` is a range annotation, not a clinical class; the convention is encoded in three places
  across two other repos (producer + two consumers). Strip `OUT_OF_`, **not** `OUT_OF_RESULT_`.
- The tag depends on **how the range string was rendered**, not the value: same sample, same `>90`,
  `EGFR` (`60-90`) → `OUT_OF_RESULT_NORMAL` but `EGFRAA` (`>=60`) → `RESULT_NORMAL_M`.
- The porting contract shift: legacy Java **derived** the class from the value, emr-v2 **trusts a
  precomputed label** from gRPC — which is why an enumerated switch was guaranteed to run short.
- What TNP actually looks like on the wire (OBX-8 blanked **plus** an `NTE|…|Test Not Processed`).
- OBR panel labels: delivery success ≠ content correctness; the `testHierarchyForReports` API,
  the category→EMR-code mapping, and the disproved "smallest containing package" rule.
- **Same sample, different pod, different HL7** — the still-unfixed `pipeline_location` filter gap
  combined with on-prem lagging cloud releases (measured: 72 vs 87 markers).
- PF's folder being empty ≠ nothing was uploaded (it sweeps to `/Prod/Archive`).

`long-term-memory/patterns.md` (+~120 lines, two blocks):
- **Family extension**: "a fallback that is semantically a *guess* must fail loud" — VP-17631
  (silent first-match degradation), VP-17503 (placeholder PDF), VP-17524 (the counter-example
  proving the loud `default:` was the only reason the bug was visible). Plus the follow-on most
  people skip: **after making it fail loud, confirm someone is actually listening** — emr-v2 has no
  cron scanning `next_retry_at`, so an upstream outage > ~30 min means the report never ships and
  no one is watching the ERROR row.
- Describe the symptom from the artifact, not the variable (I wrote that ticket and got it wrong).
- Other teams' code is a faster, more reliable oracle than a human round-trip.
- Offline replay of a legacy algorithm is a cheap root-cause proof (both tickets, same shape).
- The full recipe for a zero-side-effect prod-data E2E via a read-only generate-content endpoint,
  including the `POD_ROLE=web` + `ENABLE_KAFKA_CONSUMER=false` inerting and why control samples are
  what turn a diff into evidence.
- "Staging can't verify this" is a real finding, not hand-waving — `validateEmrIntegration` runs
  before the mapper, so prod samples die at step 2 and never reach the code under test.
- `npm test` not `npx jest` on a fresh worktree; quote `--include` under zsh.
- **From VP-17628**: two stakeholders ruling on the same fallback may be ruling about *different
  actor classes* — key the rule by actor type instead of flattening it into one chain; and "row
  exists" ≠ "value usable" (37% usable / 37% empty-string / 26% no row across 52,615 clinics —
