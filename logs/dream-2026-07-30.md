## Pipeline fix — PR #16

The dream pipeline has been **padding every memory file with blank lines on every run**, unbounded.
`write_frontmatter()` kept the newline terminating the closing `---` as part of the body and then
re-emitted `---\n` + body, so each call inserted one more blank line. The scoring script writes twice
per run, so ~2 lines/night per file. Measured on `LBS-1541.md`: `7123d83` 99 → `9319772` 100 →
`3e4ec41` 104 → tonight 106. Over 100 STM files carried 40–80 blank lines each.

Fixed (strip leading blanks, re-emit exactly one separator — idempotent, and it normalizes
already-padded files on their next write) with a 5-case regression test. Tonight's run cleaned the
corpus: 193 files checked, **3 left with >1 blank** (LTM files whose frontmatter didn't change this
run; they normalize on their next write).

Automation change ⇒ PR, not a direct commit to main, per `CLAUDE.md`:
**https://github.com/leolin84200704/vibrant-america-working-agent/pull/16**
