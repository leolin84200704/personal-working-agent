## The verification trick worth keeping

transv2 has introspection off in both cloud envs and the agent holds no
clinic JWT, so neither `__schema` nor an authenticated call was available.
GraphQL's validation phase runs before the NestJS auth guard, so an
unauthenticated POST of the new query distinguishes "field exists" from
"field missing" without credentials: the real query returned
`UNAUTHENTICATED` (validated, reached the guard) while a bogus field returned
`GRAPHQL_VALIDATION_FAILED`. Same pair on prod and staging. This is a
schema-presence proof of the deployed artifact, not a data round-trip; the
data path was proven on 08-31 against prod calendar_prod through the compiled
dist of the same commit. Both halves are written in the STM with that
distinction, so the nightly audit does not upgrade it to "fully verified".
