## 排除過什麼

- initialOrderCenterHome 當主源：date-only 窗、無 patient 過濾、無 wrapper。
- v5_SearchSamples／v2 ownership RPC（見上，debate 證據齊全）。
- 純 patient 端 status 省略方案：Portal 單沒有 orderId/placerId，lookup mode
  永遠查不到它們——list 不帶 status = Portal 渠道全 API 無 status（這個論證
  說服了所有人，包括 spec 頁自己）。
- 對 largest-clinic 延遲加 cache：實測根本不需要。

## 為何這樣決定

- 全 v1 組合（time-range ids → 切頁 → ListSamples batch → intake join）:
  零新上游、全部 prod-live、liveness 已證。global sort key = sample_id 是
  文件化的近似（穩定 unique-key 分頁換取無重無漏）。
- patientId 零 in-scope rows → 404 統一口徑：不洩漏病人在別家的存在性。
- offsetless datetime 直接 400：core 端會用 pod 時區重讀，猜比拒收危險。
