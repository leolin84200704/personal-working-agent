# VP-17559 — app-direct Key Vault for the cloud Kafka credential

## Origin
Leo 2026-07-30: "kafka 配置最好 app 直接连 keyvault 不要通过 configmap", after I proved emr-v2's
result consumer has been silently on on-prem Kafka in prod.

## The finding (live prod pod, verified)
`KAFKA_CLOUD_SASL_PASSWORD` is an EMPTY STRING in both `lis-emr-v2-config` and
`lis-emr-v2-config-prod`; `buildCloudKafkaConfig()` returns null on an empty password, so every boot:
`Cloud Kafka config incomplete … skipping cloud` -> `☁️→🏠 falling back to on-prem` ->
`✅ Kafka consumer running on onprem cluster, topic=lis-general-events`.
Misleading signals that hid it: consumer group named `emr-result-consumer-cloud-production` (set as a
pod-level env override in the deployment, wins over envFrom) and the log line `pipeline location: cloud`.

## Ground truth discovered (reusable)
- **App-direct Key Vault already exists** in `LIS-backend-v2-order-management`: vault
  `https://vibrant-app-secret.vault.azure.net` (`common/const.go:27`), secret
  `kafka-sas-connection-string` (`common/config.go:86`), credential = WorkloadIdentityCredential on
  AKS / DefaultAzureCredential locally (`common/config.go:38-54`).
- That secret serves the Event Hub namespace with `general-sample-events` (prod) /
  **`general-sample-events-staging`** (staging) — `global/constant.go:10-11`. emr-v2's ConfigMaps
  hardcode the PROD topic for both envs = latent staging bug, fixed in the template.
- **A different vault** `jwt-rsa-private` is the CSI-mounted one (order / coresamplesv2 / oauth /
  issue / lis-results namespaces, `/mnt/secrets-store/<objectName>`). Do not confuse the two.
- Cluster already has the workload-identity webhook + Secrets Store CSI CRDs. Existing workload
  identity client ids: `ae63b423-110a-4873-8dc3-369415150fa2` (order/bkkeeping/charging/default) and
  `70b999e5-9a9a-43e9-b697-75eda5981c79` (coresamplesv2). emr-v2 namespace had only the `default` SA.
- Event Hub connection strings also sit in other namespaces' ConfigMaps (e.g.
  `default/lis-corelisv7-config` key `AZURE_SERVICEBUS_GENERAL_SAMPLE_EVENTS_CONNECTION_STRING`,
  namespace-level RootManageSharedAccessKey on general-events) — usable to read the hub ad hoc.
- Distroless pods (order, coresamplesv2) have no shell -> `kubectl exec` cannot read their mounts.

## Change (PR #311 draft -> staging, branch feature/leo/VP-17559)
`KeyVaultService` (cache, 10s timeout, warn+null never throw, failed reads not cached) + listener
resolves the SASL password from the vault; env var kept only as local-dev override and an EMPTY value
falls through to the vault. ConfigMap template drops the secret slot, adds `AZURE_KEY_VAULT_URL` +
`KAFKA_CLOUD_SASL_SECRET_NAME`, documents the staging topic. Both AKS manifests get an
`emr-v2-workload-identity` SA + `azure.workload.identity/use` label.
Tests: 6 KeyVaultService + 6 listener cases; 25 suites / 265 pass; tsc clean; nest build OK.
