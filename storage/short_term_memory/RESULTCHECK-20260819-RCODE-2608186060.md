## Diagnosis chain (2026-08-19)
1. `result_transmission_records`: **0 rows** for sample 2617865 (also 0 in legacy
   `result_records`, `hl7_result_cache`; `emr_sample.result_sent=0`). Nothing was
   ever pushed — that is why Cerbo shows nothing.
2. Pipeline itself healthy: cust 4953 had TRANSMITTED pushes through 2026-08-18.
3. `getReportStatusListV2?barcode=2608186060`: **10/10 reports Pending, EDR
   "Awaiting Sample"**, finished_reports=0, blocking issue "No Finished Test"
   ("no test in this sample has finished yet"). Reports: HM2, MY2, ET2, OAC, VA,
   TB2, CIP, FS, CDZ, NTZ. So no-push is CORRECT behavior — there is nothing to
   generate yet. (Order placed only 2026-08-18.)
4. Inbound order verified: hl7_file_input 6877 `order_5136_1787058658_13.hl7`
   (received 2026-08-18 13:15:47Z, parse_finished=1, no error flags). The order HL7
   carries a single OBR **VACP151546** "JULY 2026 Biologic Code / Concussion Code
   (No Genetics)" → custom bundle **112328** ($2350 customerPay, payment_id present).
   Individual markers never appear in MDHQ order HL7s — expansion happens in our
   bundle definition, so "the HL7 file doesn't list the markers" is expected and not
   a defect. (Original file pulled from MDHQ SFTP /rcode/orders/archive/ to verify.)
5. Marker presence confirmed: `testHierarchyForReports?barcode=2608186060` contains
   all four — **Anti-tTG IgG\*, Anti-tTG IgA\*, Anti-Gliadin IgG\*, Anti-DGP IgA\***
   under **Vibrant America > Celiac > Celiac & Gluten Sensitivity**. They will be in
   the VA report and its HL7 OBX once resulted.
6. Push expectation for this accession: no GUT5 ordered → PER_REPORT_GROUP
   edge case collapses to a **single final whole-order push** when all 10 reports
   finish (VP-17715 semantics: GROUP:MAIN requires remaining≠∅, false here).

## Action decision — regeneration NOT executed
Leo asked to "try generating once to see if there is a difference". Repush
pre-check requires *report actually finished* — fails here (0 finished tests).
A forced generate+send now would either throw (no PDF/no results, VP-17503
fail-loud) or deliver an empty result file onto the practice's live Cerbo SFTP.
No difference is possible until at least one test results. Declined and reported
instead; whitelist action stands ready once reports finish.

## Auth gotchas hit (worth remembering)
- `getReportStatusListV2` + `testHierarchyForReports`: `Authorization: <token>`
  RAW, **no Bearer prefix** — with Bearer both return 401/Unauthorized. (LTM's
  note "must have Bearer" applies to getLegacyBundleMapping with ORDER_API_TOKEN;
  with VIBRANT_API_TOKEN the pricing endpoint explicitly rejects 'bearer '.)
- Prod lis_emr from this sandbox now requires TLS: mysql2 needs
  `ssl:{rejectUnauthorized:false}` or connection is refused
  (`--require_secure_transport=ON`).
