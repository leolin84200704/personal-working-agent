# VP-17685 - Closeout Audit Record

> This file was created by the **dream closeout audit** on 2026-08-12, not by the work
> session — the work session left no STM. Content below is only what dream verified
> against ground truth (GitHub, kubectl, Datadog). The design rationale lives in the
> Jira description, which is unusually complete for this ticket.

## Ticket Analysis

`OrderFinalizerService.finalize()` asked coresamples **v2** for the julien barcode on any path
where payment had not already supplied one. That RPC fails 100% — v2's image is `FROM scratch`
with no `/usr/share/zoneinfo`, no embedded `time/tzdata`, no `TZ`/`ZONEINFO`, and
`sample_service.go:1929` calls `time.LoadLocation("America/Los_Angeles")`. Broken since
2025-02-19 (`7d0f2732`), silent because a barcode failure is caught and logged at warn.

Prod never surfaced it: a successful customerPay charge already carries `julien_barcode`, so only
no-charge / replay paths reach the RPC. Staging (charging broken) hit it on every such order.

## Decisions Made

Call **v1**, do not patch v2. VP-17318 (2026-07-02) had already moved the order path off v2's
`GenerateSampleID` after finding it ~311k ids behind `lis_core_v7.sample`. v1 implements the same
proto shape with `moment.tz` on a `node:22` image. Patching tzdata in v2 would only make an unfit
dependency look usable.

## Failures

**The fix as first shipped could not call the RPC at all.** Datadog, staging:

```
generateBarcodeForSampleID failed for sample 2554096-2554098:
  client.generateBarcodeForSampleID is not a function
```

×3, 2026-08-12 20:03:53Z → 20:15:06Z — i.e. after #343/#344 were live and after Jira said Done.
The gRPC client object exposes the method under its **proto** name; the camelCase alias the code
used drops the trailing acronym (`...ForSampleID` → `...ForSampleId`), so the property was
`undefined` and the call threw. #348 fixed it.

Nothing caught this before prod:
- `npx jest src/modules/grpc src/modules/hl7-order-processing` → 31 suites, **375 passed**
- `npx tsc --noEmit` → 0 errors; `nest build` clean
- the restored CI gate (VP-17656) ran and passed

All three were green because the client is **mocked** in the specs — a mock happily answers to
whatever name the caller invents, so the specs asserted the wrong name and agreed with themselves.
See the lesson extracted to `long-term-memory/patterns.md`.

## Retrospective — why this is FLAGged, not PASSed

The chain has one hole, and it is the one that matters:

- **No live verification, ever.** The ticket's own description ends "Still to do after deploy:
  place an order on a no-charge path against staging and confirm `hl7_file_input.julien_barcode`
  is populated." Datadog for `generateBarcodeForSampleID|julien_barcode|generateAndSaveBarcode`
  across both prod and staging since the 21:51Z deploy returns **0 rows of any kind** — no
  success, no failure. The only live evidence this code path has ever produced is the three
  `is not a function` failures from the broken version.
- **Done was transitioned at 18:41Z**, 60 seconds *before* #343 merged to staging, and ~2h before
  the code first became capable of working. The Done timestamp is evidence about intent, not
  about the system.

So: the right fix, correctly deployed, with its own stated acceptance step unperformed. The
barcode either mints now or throws a different error, and nobody has looked.

## Lessons Learned

1. **A mocked collaborator cannot validate the name you call it by.** 375 green specs + clean
   `tsc` + a green CI gate, and the very first live call threw `is not a function`. The seam the
   mock replaces is exactly the seam that broke. Distilled to `patterns.md`.
2. **"Done" set at merge-to-staging time is a claim about a queue position**, not about behaviour —
   and here two more PRs to the same ticket landed after it. Second independent instance of the
   VP-17474 pattern; the closeout audit exists for precisely this and caught it inside 7 hours.
3. **A non-fatal catch converts a 100% failure into a silence.** This RPC failed on every call for
   ~18 months and cost nothing but a warn line, so no one looked; the only reason it surfaced now
   is that staging's broken charging forced every order down the no-charge path.
