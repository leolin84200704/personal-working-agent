## Where it lived

`LIS-setting-consumer/src/setting-consumer/pns.service.ts`, method
`notify_customer_billing_delta_payout_initiated_billing_delta_credit_pending()`
(~line 10930). One consumer on `TOPIC_GENERAL_EVENT` /
`TOPIC_GENERAL_EVENT_AZURE` handles **five** `lis-payout` events:

| event_name | prod | non-prod |
|---|---|---|
| `billing_delta_payout_initiated` | email (35930236) | email (37608028) |
| `billing_delta_credit_pending` | email (36513633) — **retired here** | email (37608029) |
| `billing_delta_credit_disbursed` | early `return` | email (37977025/38095775) |
| `billing_delta_payout_disbursed` | early `return` | email (37977084/38095783) |
| `billing_delta_cashout_disbursed` | early `return` | email (37977088/38095776) |

So after this change prod sends exactly one email from this consumer:
`billing_delta_payout_initiated`.

Producer side is `LIS-backend-v2-payout/service/producer.go`
`SendCreditPendingEvent()` — untouched, the event keeps being produced.

## What changed

New `src/setting-consumer/billing-delta-events.ts`:
`sendsBillingDeltaEmail(event_name, envm)` = the whitelist **plus** the
pre-existing prod-only exclusion of the three `*_disbursed` events, folded into
one predicate. Consumer's outer `if` calls it, and the nested prod early-return
block is gone (equivalent, one indentation level less).

Removed:
- `billing_delta_credit_pending` from the whitelist, from the `template_id`
  else-if chain in the consumer, and from the `template_model` branch in
  `patientPay()` (~line 2604).
- Dead code from 075e5dc: the commented-out `allowProvidersUsingBillingDelta`
  gate, the commented-out `beta_program` gate, and the locals that only fed them
  (`clinic_id`, `is_beta`, `beta_program_enabled`, `beta_programs`). Note the
  outer `clinic_id` was already shadowed by an inner
  `const clinic_id = await this.getClinicFromSample(...)`, so nothing read it.

New `billing-delta-events.spec.ts`: 6 tests, all five events x prod/non-prod.
Follows the `report-product-list.ts` + spec precedent already merged in this repo
(VP-9299) — extract a pure function, test it, leave the Kafka monolith alone.

## Scope item 3 — template exclusivity

`36513633` / `37608029` appear nowhere else. Checked
`LIS-setting-consumer`, `LIS-notification-center`, `LIS-transformer`,
`LIS-transformer-v2`, `LIS-backend-v2-payout`, `LIS-backend-v2-billing`,
`LIS-backend-billing`, `pns-portal`. Exclusive to this event.

**NOT DONE — needs Leo**: marking the template deprecated is a Postmark-side
rename, an action on an external service. No Postmark API token exists in
`~/src/credential/` (only 2FA backup codes), and the ticket says no hard delete.

## Deliberately not renamed

The method name and the env var
`CONSUMER_GROUP_ID_consume_billing_delta_payout_initiated_billing_delta_credit_pending`
still carry the retired event's name. Renaming the method churns the `func`
strings written to `lis_front_logger`; changing the consumer group id would reset
offsets and re-read the topic from its retention start. Left as-is on purpose,
stated in the PR body.
