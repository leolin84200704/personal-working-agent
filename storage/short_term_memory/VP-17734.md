## Part 1 — Delivery: the repush went to the wrong accession

### [2026-08-18] Diagnosis
`result_transmission_records` for sample 2590476 held **exactly one row** before today:
`cms50ne3j0031t8077s3ziqxu`, created **2026-07-28 18:55:37Z**, GENERATED/ENCODED/
**TRANSMITTED** to `/public/2607066235.hl7`, 3,596,364 B. `updated_at` never moved,
so not even the 24h record-reuse path had touched it — i.e. **no repush of this
accession ever happened**.

Fleet-wide, the only manual repush (`created_by='result_generation_service'`) for
customer 4478 in the last 4 days was **2026-08-18 18:20:07Z for accession
2301020116 / sample 796594** — the 2023 Gut Zoomer 3.0 accession Yekai had already
identified as the wrong one, repushed 11 minutes *after* Zhenhe posted the corrected
accession. That is why the provider saw nothing: the corrected report was never sent.

> Timezone trap: `mysql2` renders lis_emr DATETIMEs (session tz `+00:00`) through the
> Node process's local zone, so JSON output is shifted **+7h**. Always read timestamps
> with `DATE_FORMAT(col,'%Y-%m-%d %H:%i:%s')`, never the ISO string.

### [2026-08-18 22:15Z] Action — repush executed (Class A whitelist)
`POST http://192.168.60.5:31318/api/v1/result/generate/2590476 {"send_result":true}`
with a 15-min HS256 admin JWT (`JWT_SECRET_PROD`, `internal_user_role=admin`), against
the **on-prem** prod pod (correct owner: `pipeline_location=onprem`; its uptime was
13,251s, i.e. redeployed 2026-08-18 18:33Z, so the 2026-08-17 stale-deploy drift is gone).
HTTP 201 in 32.4s.

## Part 2 — Content: the classic PDF itself is defective (report team, not EMR)

The provider's actual complaint reproduces, and the cause is upstream of emr-v2.

Evidence chain, all from the **delivered artifact** (base64 ED OBX decoded out of the
file pulled off P2P's own SFTP):

1. **HL7 discrete data is complete.** OBR-3 (Gut Zoomer 5.0) carries all 28
   neurotransmitter OBX — Serotonin 215.25 H (51.20-127.90 mcg/g), GABA 174.67 N,
   Glutamate 10659.28 H, Dopamine 135.66 N, DOPAC/HVA/VMA/3-MT/Metanephrine/… —
   all resulted 2026-07-23 03:52Z, five days before the report was built.
2. **The embedded PDF has the section headers but no tables.** 109 pages; TOC p53
   points at "Gut Neurotransmitters Pg 73"; pages 73/74/76/77 contain the header and
   nothing else (427 chars of text each, identical to the uncompressed source), p75 is
   the Tyrosine-metabolism diagram, p78 only "Supplement Suggestions". Compare p71
   (Gut Metabolites) which renders a proper Current/Ref-Range table.
3. **Not a compression artifact.** The pipeline downloads the cached classic PDF
   (13,331,702 B) and Adobe-compresses it because POWER2PRACTICE falls to the DEFAULT
   10MB threshold; the compressed result is 2,660,284 B, **109 pages, page-for-page
   text-identical** to the source. Compression removed nothing.
4. **Not a data-availability problem.** The **advanced** PDF for the same accession,
   `CreationDate 2026-07-28 11:55:46 PDT` — 16 seconds *before* the classic one —
   renders Serotonin 215.25 / GABA 174.67 / Glutamate 10659.28 / Dopamine 135.66.
   Same data, same minute, only the classic style is empty.
5. **Not accession-specific — it is a generation-time window.** Downloading
   `pdf-cache/download/{acc}?style=classic` for other GZ5 accessions and checking for a
   `(Serotonergic|Dopaminergic|GABAergic|…) Pathway  Current` table:

   | classic PDF CreationDate (PDT) | accession | neuro tables |

   | Jul 22 21:41 | 2607086219 | OK |
   | **Jul 28 11:56** | **2607066235** | **EMPTY** |
   | **Jul 30 18:39** | 2606196595 | **EMPTY** |
   | **Jul 30 18:46** | 2607136133 | **EMPTY** |

   4/4 in-window empty, 7/7 outside populated. Last known good **Jul 22 21:41**,
