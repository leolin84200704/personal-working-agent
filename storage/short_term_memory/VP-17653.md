# VP-17653 — Speed up emr-v2 CI/CD (~20 min builds)

Jira: https://vibrantamerica.atlassian.net/browse/VP-17653
PR (draft, target staging): https://github.com/Vibrant-America/lis-backend-emr-v2/pull/335
Branch: feature/leo/VP-17653 (worktree lis-backend-emr-v2.worktrees/VP-17653)

## Diagnosis

### [2026-08-10 — root causes of the 20-min build]
1. Sequential rollout waits: main build waits on-prem (2x `rollout status --timeout=300s`) THEN AKS (`--timeout=420s`); staging same shape. Deploys are independent once images are pushed.
2. Dead prepare-stage work: `npm install` + `npx prisma generate` + `npm run prisma:generate:test` on the agent — consumed by nothing since the test stage was deleted (commented out 2025-09-17 by zichen.z in "Fix AutoIntegration Auth Missing Issue", removed 2025-12-08 "remove commented code").
3. No .dockerignore: `COPY . .` shipped workspace node_modules/.git/kubectl binary/exported ConfigMap yamls into every Docker build context. `.env` must stay in context (Setup Env File stage injects it for the image).

Also noted (NOT in this ticket's scope):
- No test/lint guardrail at all in CI; feature/PR branches trigger nothing (only main/staging build). Leo wants to discuss re-adding tests after this lands.
- Registry credentials (internal + ACR) hardcoded in Jenkinsfile.
- Repo has 82 *.test.ts files + full jest scripts, unused by CI.

## Fix (4 commits on the PR)
1. .dockerignore (new)
2. prepare stage: keep GIT_* env exports, drop install/generate
3. main: ACR push moved before deploy fan-out (preserves VP-17291 pin-to-SHA invariant), ConfigMap export shared, then `parallel` on-prem + AKS
4. staging: ACR push up-front gated by DEPLOY_STAGING_TO_AKS, then `parallel` on-prem + AKS staging

## Gotchas hit
- Edit slip: dropped the `script{}` closing brace while wrapping the staging block — caught by brace-count check vs origin/staging (89/89 → must stay balanced). No local groovy linter; first staging build is the real syntax validation.
- pre-push hook failed in fresh worktree: no node_modules → `npx prisma generate` fetched Prisma 7.9.1 which rejects `url = env(...)` in schema (P1012). Fix: `npm ci` in the worktree so the pinned prisma@6 is used. Do NOT --no-verify.
