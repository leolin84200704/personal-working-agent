# VP-17537 — accession_id missing from place-order payload (customerPay)

## Origin
api-product feedback during 2026-07-29 sandbox order testing: "customer pay 的情況下 order payload
裡傳了 sample id 但沒傳 accession id". Filed by me (own-scope defect rule). Same session that
diagnosed the customerPay charge failure (charging ACH path).

## Analysis
- Place Order contract: `place-order.dto.ts:96-99` marks BOTH `sample_id` and `accession_id`
  "required if payment made". `toPlaceOrderRequest` (order-request.mapper.ts) only mapped `sample_id`
  — `accession_id` was never wired since VP-17283.
- The value was already in hand: customerPay charges BEFORE placement; charging
  `POST /transaction/pay` returns `sample_id` + `julien_barcode`; `order-finalizer` sets
  `orderFrontend.julienBarcode` on both the fresh-charge branch and the VP-17497 replay branch;
  `order_intake.julien_barcode` persists it.
- **julien_barcode IS accession_id downstream** — order-management
  `handler/order_billing_sample_info.go:289` builds `"&accession_id=" + julienBarcode` from
  `lis_re.order_table.julien_barcode`; emr-v2 result pipeline maps
  `accessionId: sampleInfo.julienBarcode` (result-generation.service.ts:614/1505).
- The API *response* to the caller already carries `accessionId` (from the place-order response,
  `order-intake.service.ts` return) — the gap was only the OUTBOUND payload. Scope reading
  confirmed pending with Leo.

## Change
`accession_id: of.julienBarcode || undefined` in `toPlaceOrderRequest`. Truthiness guard:
patientPayLater generates the barcode only after placement, and 0 is never a valid accession.
Branch `bugfix/leo/VP-17537` (worktree, base origin/staging), draft PR #304 -> staging.
Tests: mapper spec +2 cases; 22 suites / 230 tests pass; tsc clean; pre-push nest build OK.
