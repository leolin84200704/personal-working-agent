# VP-17595 — result consumer cloud-only

## Origin
Same 2026-08-04 on-prem decommission audit as [[VP-17593]]/[[VP-17594]]. Leo: "emr 也改一下".
emr-v2's only real Kafka consumer is the report-finished listener (kafka.service/consumer/producer
are TODO stubs). Cloud Event Hub primary since VP-17561 cutover (2026-07-29, stable); on-prem
brokers 60.9/10/11 remained as fallback in code (hardcoded default!) and ConfigMaps.

## Change (PR #318 draft -> staging, branch bugfix/leo/VP-17595)
- connect() cloud-only; failure throws with the real cloud-side cause (was: 8 retries against dead
  brokers then a misleading "both failed").
- KAFKA_CLOUD_ENABLED=false => throw at startup (config error). ENABLE_KAFKA_CONSUMER=false stays
  the intentional off switch. Rationale: silent non-consumption is the known result-delivery
  failure mode.
- Removed buildOnPremKafkaConfig + hardcoded 60.x default + KAFKA_TOPIC/KAFKA_BROKERS reads;
  configmap template updated with post-deploy live-CM cleanup note.
- Tests: +3 spec cases; listener spec 20/20; full suite 1086 pass; tsc clean; nest build OK.
