## Working hypothesis (unconfirmed — needs Datadog)
Failure was systemic on the server side during an Aug 6-8 window and was cleared by the 08-08 pod replacement. Top suspect: wedged Puppeteer browser pool — `/health` returns ok WITHOUT exercising the pool (server.js:116), so a dead pool passes liveness forever while every /pdf 500s (poolAcquireTimeout 10s). Matches: every report/account/network fails, render-side (viewer) still fine, nothing reproducible after 08-08.
Ruled out for the live my-calendar flow: CORS (allowed + verified), engine auth (none), token mismatch, gateway timeout (engine max 33s < 60s), report-pdf FE code path (works today end-to-end).

## Hardening items found (regardless of root cause)
