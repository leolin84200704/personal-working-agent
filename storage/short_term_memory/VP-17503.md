# VP-17503 — Remove whole-order placeholder-PDF fallback (fail loudly)

## Ticket Analysis
### [2026-08-06 10:30]
- Filed by us 2026-07-27 from VP-17493 code inspection (whole-order path was intentionally out of VP-17493 scope). Leo reclassified Bug -> Story ("這也不是bug") and moved Inactive -> Dev To Do this session, then said start.
- 4-part (Gate 1):
  1. 目的: a whole-order push whose PDF download fails must not silently deliver a junk placeholder PDF marked GENERATED/TRANSMITTED.
  2. 改前: `generatePdfReport()` on missing accession id or exhausted download returned hardcoded base64 placeholder (2 branches) unless `throwOnFailure` was passed; only partial pushes passed it. Whole-order callers got the placeholder, HL7 encoded/uploaded, record marked success. Dev-era `sample_id === 2099046` branch substituted accession 2405306314's PDF.
  3. 改後為何有效: throwing lands in `generateResultHl7`'s existing catch -> record marked GENERATION_ERROR (category/code/message, retry_count+1, next_retry_at) -> `success:false` -> processor throws (VP-17342) -> BullMQ retry. Transient PDF outages self-heal; persistent ones leave a visible, re-pushable record.
  4. 改什麼: `generatePdfReport` always throws (option removed); both placeholder returns + both 2099046 fallbacks deleted; partial call site keeps catch/degrade (drops `throwOnFailure`, keeps `maxDownloadRetries: 0`); whole-order keeps default download retries (10/20/40s backoff).

## Approaches Considered
### [2026-08-06 10:40]
- A (chosen, Leo confirmed via AskUserQuestion): throw -> GENERATION_ERROR + BullMQ retry. Zero schema change, reuses VP-17342/17493 machinery, consistent with "fabricating placeholder data is worse than failing" postmortem rule.
- B (rejected): degrade whole-order to data-only + explicit flag on the record. Needs schema change, and whole-order is the *authoritative* PDF delivery (VP-17493 comment) — degrading it means the PDF is never delivered by anyone.
- NOT touched: `getClientConfiguration`'s customerId 999997/clinicId 10136 special case (test-account client config, used by reference-HL7 spec fixtures) — different thing from the PDF fallback, out of scope.
