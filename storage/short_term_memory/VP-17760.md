# VP-17760 — Portal API: GET /orders (order status lookup)

## Ticket Analysis

- Parent epic VP-17290 (Partner Platform V1). Reporter Nan Wu. Contract:
  https://apidemo.mintlify.app/api-reference/orders/status — documented but 404s
  today. Motivation: POST /orders takes 6.6–10.8s on staging; customers time out
  on calls that DID place the order, and the only recovery is resending the same
  placerId (a write to answer a read), impossible when placerId was omitted.
- Scope: LOOKUP MODE only — `GET /orders?orderId=` or `?placerId=` (exactly one).
  List mode (patientId/from/to/page…) is VP-17975, blocked by this ticket.
- Blocker history: cancellation block (cancellable/fee/reason) had no read-only
  source; order team's only endpoint actually cancelled the order. UNBLOCKED
  2026-08-27: order-management shipped `GET /orders/cancellation-preview`
  (sample_id query param; is_cancellable / not_cancellable_reason /
  cancellation_fee / amount_to_be_refunded). Confluence 2593816583 updated by
  Fangyuan Yang 2026-08-27. Probed staging+prod URLs: 401 MISSING_TOKEN, but
  gateway auths before routing (bogus path also 401) so liveness is unproven
  from outside — must verify with a real token as step 1.
- Field decisions already made (Jira comments 183880/183942, 2026-08-13):
  - DROPPED from contract: kit.shippedAt, kit.deliveredAt, kit.carrier,
    report.availableAt, exceptions[].raisedAt. kit = status + trackingNumber;
    exceptions = type/blocksReport/detail. NOTE: mintlify still shows the old
    full shape — api-product needs to update it.
  - status lifecycle mapping (validated against 60 prod orders via shipping svc):
    READY_FOR_SHIPMENT→placed, LAB_SHIPPED_KIT→kit_shipped,
    PATIENT_RECEIVED_KIT→kit_delivered, READY_FOR_RETURN_SHIPMENT→kit_delivered,
    SAMPLE_SHIPPED_BACK→sample_in_transit, LAB_RECEIVED→sample_received; then
    analyzing / report_available from report service; cancelled from our row.
  - Preliminary Report Available → maps to `analyzing` (proposed 08-13, no
    objection; rationale: premature report_available stops customer polling
    before the final report; partial availability visible via
    generatedReportCount vs totalReportCount).
  - orderId stored since PH-855 (order_intake.order_id, nullable, never
    backfilled) — pre-08-13 orders identified by placerId only.
- Contract wrinkle found 2026-08-27: mintlify `cancellation.reason` is an enum
  [free_before_kit_ships, fee_after_kit_ships, sample_received,
  already_cancelled] — NOT the raw order-management errorMessage. Preview's 6
  not_cancellable reasons (already canceled / WellProZ / sample received /
  non-lab only / merchandise / family bundle) must be mapped; WellProZ,
  merchandise, family-bundle, non-lab cannot occur for API-placed orders
  (API path places lab test orders only) — decide fallback for unmappable.
- `amount_to_be_refunded` is UNCLAMPED (can be negative, e.g. unpaid + kit
  shipped → -25); actual cancel clamps at $0. Treat negative as fee>paid.

### Injected lessons (ENGINEERING-LESSONS, sparse k=2)

- **Verified means live, not mock** — 別把 mock unit test 說成「線上驗證」。prod
  行為的結論要用真實 DB / 部署中的 service 重現。(→ staging E2E with real token
  against real preview endpoint before claiming done; preview liveness itself
  unproven until an authenticated call succeeds.)
- **Read the helper before you build on it — stubs log success** — 依賴既有
  helper/service method 前先讀它的實作，不能只看名字和回傳型別。(→ this endpoint
  builds on existing core/shipping/report clients; read each implementation,
  don't trust method names.)

## Approaches Considered

### [2026-08-27] Design v1 (post-Explore, pre-debate)

- New OrderStatusController @Controller(['order-status','order-intake']) @Get()
  — VP-17531 gateway forwards /v1/orders/* onto /api/v1/order-intake/*, so
  GET /v1/orders?orderId= lands on GET /api/v1/order-intake. Same guard stack
  as order-cancel (JwtAuthGuard + PartnerApiErrorFilter +
  PartnerRequestIdMiddleware, customer-scoped token required,
  ORDER_INTAKE_MODE gate with dryrun==live for read-only).
- Identifier rule: exactly one of orderId|placerId (PH-853). Tenancy = one
  customer-scoped findFirst (order-cancel.service.ts:37-49 pattern); 404
  unified message (no existence leak, fhir pattern). Row visibility: only
  finalized+cancelled → 200; received/rejected/failed/ineligible/dry_run → 404
  (failed rows: 404 → caller re-POSTs → VP-17497 reclaim works).
- Fan-out from row.sample_id: core listSample (existing) ∥ core
  getSampleRelevantInfo (patientId) ∥ NEW shipping gRPC
  GetKitStatusBySampleId ∥ NEW CancellationPreviewClientService (mirror
  CancelOrderClientService: TokenHelperService minted token,
  ORDER_CANCELLATION_PREVIEW_{PROD,DEV}_URL); then report service
  getReportStatusListV2?barcode= (needs accessionId from core).
- Shipping endpoints (from LIS-transformer-v2 prod config + VP-16784 STM):
  cloud lis-shipping-service-grpc.shipping.svc.cluster.local:63142, on-prem
  192.168.60.6:31865; add shipping/shippingCloud to grpc.config.ts +
  tryCloudThenOnPrem. proto already vendored (src/proto/shipping.proto, has
  GetKitStatusBySampleId). Send-status values confirmed in transformer
  trans.service.ts:146 map (READY_FOR_SHIPMENT/LAB_SHIPPED_KIT/
  PATIENT_RECEIVED_KIT). Staging shipping endpoint unknown — config optional,
  kit block degrades to null when unset/unreachable.
- Status precedence: cancelled > report_available(Final) >
  analyzing(Preliminary per PM decision/Analyzing) > sample_received >
  sample_in_transit > kit_delivered > kit_shipped > placed.
- Degrade: core listSample fail → 503 (wrong status worse than no answer);
  shipping/report/preview fail → block null + warn. Cancelled rows skip
  preview call.
- Explore key facts: PH-855 commit 4047c0d is the explicit precursor (order_id
  column applied to staging+prod DBs already); no index on order_id/sample_id
  (table-scan — check row count before deciding index migration); DTOs are
  interfaces NOT class-validator (global pipe forbidNonWhitelisted would break
  real DTO classes); error envelope opt-in = @UseFilters + middleware
  forRoutes; JwtAuthGuard.validateDataAccess reads query.customer_id (our
  params don't collide); report svc consumed via fhir-result.service.ts
  enrichFromReportService (barcode-keyed, sample_level_report_status counts +
  issues; upstream typo report_staus handled); test convention = plain-object
  DI mocks, specs co-located.

### [2026-08-27] Debate outcome (design v2)

Critic objections ACCEPTED: (1) own-tenant rows visible in ALL statuses — 200
with extended status processing/rejected/failed/dry_run for non-finalized rows
(404-for-received defeats the recovery use case: stuck received row = GET 404 +
re-POST duplicate/null forever, VP-17686 comment documents the black hole);
CONTRACT EXTENSION — needs api-product/mintlify update, flag to Leo + draft
comment for Nan. (2) gateway base-path GET unverified → also register
order-intake/status subpath (proven passthrough) + order-status direct; E2E
verifies both incl. query-string survival. (3) 5s per-upstream timeout, ~10s
overall budget (report call sequential after core). (4) patientId from
request_json (controller guarantees numeric patient_id pre-intake), drop
getSampleRelevantInfo RPC. (6) scopeless tokens die 403 at guard (document,
don't claim 400); reject unknown query params (closed surface). (7) core
sample-NOT-FOUND ≠ outage: not-found → degraded row-only 200 (esp. cancelled
rows); transport error → 503. (8) status precedence + degrade matrix as PURE
FUNCTION tested exhaustively; supertest boot test for route/middleware
registration; E2E checklist incl. one real shipping gRPC call (VP-17318
keepCase field-name incident class). (9) (customer_id, order_id) index in this
PR (manual ALTER before deploy); findFirst orderBy id desc; dry_run rows
visible as dry_run.

Critic REJECTED on: cutting the cancellation-preview leg — critic lacked the
context that the upstream preview API was published today (Confluence
2593816583 §2, the unblocking event). But its string-matching attack stands:
reason enum derived from OWN structured signals only (already_cancelled from
own row/core ORDER_CANCELED_STATUS before calling preview; sample_received
from core sampleReceivedTime; fee>0 → fee_after_kit_ships; else
free_before_kit_ships; unmappable → reason null + warn with raw message).
Preview liveness still unproven from outside (gateway 401s pre-routing) —
degrade-to-null covers non-deployment; authenticated staging probe is E2E
step 1.

Commit plan (revert-boundary lesson): c1 clients + pure derivation fn + tests
(inert) → c2 controller/service/wiring (behavior) → c3 config/schema/docs.
