# VP-17715 — PER_REPORT_GROUP push level (exactly two deliveries)

## Ticket Analysis

### [2026-08-14 11:00]
- Customer (Dr Prusmack cust 4953, via Terry) demanded: report comes through ONLY TWICE —
  once when everything except Gut Zoomer is resulted, once when GZ results IF it results.
- Current PER_SAMPLE_TYPE delivers 6-8 interim pushes + final (counted from their real
  orders); each interim can miss late-approved CALCULATION analytes (the +12 wellness
  scores/ratios found 2026-08-13) because `sample_type_all_finish` gates only on
  instrument-measured tests. Specimen type is also lab-internal (Urine vs Metal Free
  Urine = different collection containers; Serum vs SERUM = duplicate catalog entries).
- Filed by us after Leo decision ("我們要改過來"). Jira: VP-17715 (Story, Dev To Do).

## Key design decisions

### [2026-08-14 11:20]
- **Trigger = report readiness, not test approval**: `new_report_status_updated` addon
  carries `total_reports_short_names` (full expected set INCLUDING not-yet-generated,
  e.g. GUT5) + `generated_reports_short_names` — verified against ClickHouse
  kafka.general_sample_events for accession 2607166082 (10/11 generated, GUT5 pending).
  Report-ready also inherently includes calculated analytes.
- **Phase 2 = existing whole-order push**: report_finished fires when ALL reports incl.
  deferred are final; push levels never filter the final push. So NO new phase-2 code —
  main push condition requires `remaining ≠ ∅` so the final never duplicates it.
- Condition: `mainReports = total − deferred`; push GROUP:MAIN iff
  `mainReports ≠ ∅ ∧ mainReports ⊆ generated ∧ remaining ≠ ∅`.
- Config: `ehr_integrations.deferred_report_short_names` VARCHAR(500) JSON array
  (`["GUT5"]`); empty/unparseable → no main push (degrade to whole-order-only, fail-safe).
- Dedup: scope GROUP:MAIN, repushAfterMs null (delivered shields forever, undelivered 24h
  — same semantics as REPORT scope).
- Edge cases (all fall through to final push): deferred-only accession (Demos GZ-only
  barcode 2602196752), no deferred report ordered, deferred finished first (collapses to
  ONE complete final push — open question to PM, documented in ticket).
