## Ticket Analysis

### [2026-08-14] Basic info
- Bug | P2 - Medium | **Dev To Do** | Reporter Yuchen Wang | Assignee Leo | no components/labels/links
- Title tagged **[FE]** — evidence says the defect is **BE** (LIS-transformer-v2 calendar). FE angle only exists if we choose the "FE supplies the new link" option.
- Symptom: Zoom consult transferred from one Clinical Educator to another keeps the ORIGINAL educator's Zoom room. Example in ticket: consult moved off Dr. Jessy Dhanjal; the new educator and the provider both landed in Jessy's personal meeting room; consult started late. "A few other Clinical Educators have experienced the same issue." Phone consults unaffected.

### [2026-08-14] Root cause (code)
`LIS-transformer-v2` `src/calendar/models/event/event.service.ts` — `rescheduleClinicalConsult` (VP-16520), clinician-switch branch:

```
// F-8: new event clones the original's consult/order linkage; only clinician + time change.
const created = await tx.v2_event.create({ data: {
  ...
  external_url: original.external_url,   // <-- line ~4943
  location: original.location,
  ...
}});
```

`external_url` is the meeting-info column. For a **Zoom** consult it holds the *clinician's* personal meeting room URL → cloning it is wrong. For a **phone** consult it holds the *patient's* phone number → cloning it is correct. That asymmetry is exactly why the reporter sees Zoom break and phone not.

Same-clinician (in-place) branch never touches `external_url`, so it is correct by construction.

## Approaches Considered

### [2026-08-14] Options (pending Leo)
- **A — BE resolves the new clinician's Zoom room (recommended).** In the switch branch: if `original.external_url` looks like a Zoom URL, resolve the *new* clinician's PMI (new `ZoomService.getPersonalMeetingUrl(providerId, clinicId)` = token + `GET /users/me`, no meeting creation) and store that; otherwise copy as today. Fixes every caller, no FE dependency. Open: fallback when the new clinician has no Zoom integration or the API fails (leave null vs keep old link vs derive their most-used historical PMI).
- **B — FE supplies it.** Add optional `external_url` to `RescheduleClinicalConsultInput`; FE calls the existing `generateZoomLinkForProvider` for the new clinician and passes it. Matches the ticket's [FE] tag but needs an FE ticket and leaves non-FE callers broken.
- **C — Don't clone on switch.** Blank `external_url` when it is a Zoom URL, forcing manual re-entry. Safest, no Zoom API dependency, but a UX regression vs what the reporter asked for.
- A + B are combinable: B's input field as an override, A as the default.

## Lessons Learned

### [2026-08-14]
1. **【可攜，已蒸餾】Clone 到新擁有者時，owner-bound 欄位必須重新推導而非照抄**。同一個欄位可能隨情境綁不同對象（`external_url`：Zoom = clinician 的 PMI / phone = 病人的號碼），所以 bug 只在一半案例出現、看起來像偶發。症狀恆為**無聲**且**導向前一個擁有者**。第二個 case 是 VP-16881（mirror peer 時 msh06 留成 clinic_id，routing 慣例其實是 customer_id → 報告送不到，同樣零錯誤訊號）。
2. **要證明「prod 走的是哪條 code path」，找那條路徑專屬的持久化指紋**，不要用資料形狀去推論。這次是 `v2_event_accession_audit_log.reason = 'clinician switch reschedule, original event N'`（`releaseForEvent` 寫的字串）。反例在同一個 ticket 裡：`v2_event_participant.created_at` 完全不能用來反查原地換人，因為 `replaceEventParticipants` 是 deleteMany+createMany，任何帶 participants 的 update 都會重寫它。**寫入端有沒有留下只有這條路徑會產生的字串/欄位，決定了事後可不可稽核。**
3. **PMI vs 一次性會議可用位數判別**：10 碼 `/j/` = personal meeting room（owner-bound），11 碼 = 單場排程會議（entity-bound）。反向稽核時靠這條把 9577 判為非 bug。
4. **這個 repo 必須跑 baseline 對照才能宣稱「零新增失敗」**：`origin/stage_test` 本身就有 6–7 個 pre-existing 失敗 suite（clinic.service / 兩個 practice-event-type.graphql / mypractice ×2 / utility.service）外加 flaky 的 auth.guard.spec。做法：`git worktree add` 一份 base commit、symlink 共用 node_modules、跑同一份 jest、diff 失敗清單。
5. **`prisma generate` 會改寫 `prisma2/generated/client2/*` 內嵌的絕對路徑**（原作者的 `/Users/fan.z/...` → 本機），那是 checked-in 檔案，commit 前必須 `git checkout` 還原。
6. **需要外部 API 才能推導的值，解析要放在 transaction 之外**——不要為了「一起原子」讓 outbound HTTP call 卡在開啟的交易裡。
