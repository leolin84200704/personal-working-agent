### [2026-09-01] Debate outcome — design v2

Critic ACCEPTED (design changed):
1. (BLOCKER) transformer POST /patients duplicate branch (:127-135,
   {statusCode,message,patientId}, published in docs/patient-api-v1.md:131-133)
   carries a RECOVERY id partners reuse — it is a business OUTCOME by our own
   filter philosophy. v2: leave the duplicate branch UNTOUCHED; envelope only
   true request errors (validation, auth, PUT/GET downstream >=400 passthrough
   with message preserved). Flag outcome-style alignment to PM as follow-up.
2. Pricing logging: moving Ginzap pre-auth would access-log unauthenticated
   request BODIES (PHI/security) + every healthcheck probe. v2: move ONLY a new
   request-id middleware before auth (header + c.Set); Ginzap stays post-auth
   and is changed to REUSE the c.Get id (never mint/overwrite — critic minor
   #6); auth rejections get x-request-id + envelope but remain un-access-logged
   (documented limitation, not fixed here).
3. Pricing testability: router assembly is inline in func main() — extract a
   router factory (inert refactor commit) so middleware order / panic envelope /
   auth-abort envelope get real httptest behavior tests; otherwise those are
   E2E-only.
4. Fixture reality check: of the 8 PascalCase codes only PFSAMaleOnly is
   observed in-repo (a spec mock); the other 7 come from mintlify docs. STEP 0
   of implementation: pin the real eligibility-check enum (Confluence "Order
   Eligibility Check API" + staging probes) before freezing the fixture.
5. Drift mitigation upgraded from "table in Jira comment" to: one fixture JSON
   vendored byte-identical into emr-v2 + pricing (handed to Rui), contract
   tests in each repo assert converter output over it; transformer filter is
   ported byte-identical from emr-v2 (keep the '; ' join — critic caught v1
   already diverging with "first entry").
6. emr-v2 persistence claim corrected: there is NO response_json; ineligible
   persists error = failure codes joined (order-intake.service.ts:227-233).
   v2: convert at the enrichment return (enrichment.service.ts:353) so wire and
   error column agree; historical rows stay PascalCase (mixed data — note for
   any dashboard/grep reconciliation); dry_run carries no failures (verified).

   the converter; paymentFailReason is internal text — template it, never
   verbatim.
